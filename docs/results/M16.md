## 5 Crash/corruption recovery — design

- Journaling: `harpoon-root.img` is ext4 ordered journal (guest `6.12.94-0-virt` `mount` shows `ext4` `rw,relatime` with journal). Crash recovers via journal, no `fsck` on every boot needed.
- fsck: `e2fsck -n /tmp/harpoon-runtime/data/harpoon-root.img` dry-run when VM stopped (host has no e2fsck on macOS 26.5.2 — expected `e2fsck not found` branch, guest recovery via `fsck` in initramfs is SUPPORTED).
- Backup: `cp -c` (APFS clone) or `ditto` or `cp` to `/tmp/harpoon-root-backup-<ts>.img`, `ls -lh` verifies clone size, no unbounded doubling.
