## 2 Duplicate-resource Root Cause

Tauri `bundle.resources` with `List` form `["bundle-resources/harpoon"]` uses `resource_relpath` which preserves the source path relative to src-tauri: `bundle-resources/harpoon` → `$RESOURCE/bundle-resources/harpoon`. But `prepare-bundle.sh`/`build.rs` stages to `bundle-resources/harpoon`, and Tauri also preserves the directory name, yielding `Resources/bundle-resources/harpoon`. The additional `Resources/harpoon` observed in the 01:18 bundle came from a prior manual copy or from Tauri's handling of the directory as both source and resource? In current 01:41 build after investigation, the `Resources/harpoon` tree was also present due to earlier build.rs copying? After audit, the canonical fix is to use Tauri's `Map` form to remap the source to the desired destination, eliminating the prefix duplication without hand-copying a second tree.

## 3 Ponytail Decision

1. Duplicate required? No — one tree suffices, saves 1.0G (2.0G → 1.0G).
2. Can Tauri's normal resources produce canonical layout? Yes — `BundleResources::Map` supports `{"bundle-resources/harpoon": "harpoon"}` which maps `bundle-resources/harpoon/bin/harpoon` → `Resources/harpoon/bin/harpoon` via `ResourcePaths::from_map` with `Walk` + `strip_prefix`.
3. Can prepare-bundle.sh stage exactly one source tree? Yes — stage to `bundle-resources/harpoon` once, let Tauri map it.
4. Can resolver remain without duplicate bytes? Yes — keep fallback probe for `bundle-resources/harpoon` but ship only canonical.
5. Another packaging layer necessary? No.
6. Can solved by config/path cleanup only? Yes — single-line `tauri.conf.json` change from `List` to `Map`.
7. Minimum change? Edit `tauri.conf.json` `resources` to `{"bundle-resources/harpoon": "harpoon"}`; no new daemon, updater, launch agent, symlink, download, or second copy.

Rejected: custom installer, archive format, runtime download, symlink trick, updater, launch agent, privileged helper.
