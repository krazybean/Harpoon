## CLI Contract After M10
`start [options]`, `stop`, `restart [options]`, `status [--json]`, `logs [--follow] [--lines N] [--path]`, `config show|set|reset|path`, `docker setup|status|remove|use|env`, `doctor`, `run`, `version`, `help`; `harpoon --help`, `harpoon start --help` etc. Unknown → `unknown command` + `Try 'harpoon help'` exit 2.

## Default Configuration
`cpus=2`, `memory=1024` (M6 tiers 512|768|1024, cpus 1...8). `harpoon start` with no flags uses these via `RuntimeConfig.fromEnvironment()` + user config.

## Persistent Configuration
`~/Library/Application Support/Harpoon/config.json` (fallback `/tmp/harpoon-runtime/config.json` for sandbox) with `{"cpus":2,"memory":768}` etc. `harpoon config show/path/set/reset`, atomic `.atomic` write, `loadUserConfig` validates, malformed → `Harpoon configuration is invalid: ... Config: <path>` and `doctor` reports.

## Precedence
`harpoon config set memory 768` → `harpoon start` → `Memory: 768` (status). `harpoon start --memory 1024` → `1024` this run, config still `768` (CLI > config). Verified via `status` and `config show`.

## Help
`harpoon help` now shows product description, usage, commands, start options, precedence, Docker workflow, examples, diagnostics. `harpoon start --help` etc. work.

## Status
`harpoon status` concise: `Harpoon: running PID 28400 CPUs 2 Memory 768 Docker: ready Socket ...` ; stopped → `Harpoon: stopped` or `already stopped`; `degraded`/`stale` explains WHY. `status --json` → `{"state":"running","pid":...,"cpus":...,"memoryMiB":...,"dockerReady":...}`.

## Doctor
`harpoon doctor` checks host (macOS, arm64, Virtualization), Harpoon (binary, runtime dir, kernel, initramfs, disk 2147483648, lock, PID, socket 0600), Docker (CLI, version, context `harpoon` `unix:///tmp/harpoon-docker.sock`, active context, API reachable), runtime (stale/degraded, config). Output `PASS/WARN/FAIL` + `INFO`, summary `15 passed, 0 warnings, 1 failures` when running (API check may be WARN under sandbox). Returns non-zero on FAIL.

## Docker UX
`harpoon start` hints `harpoon docker setup` if missing else `Docker context: harpoon`; `harpoon docker status` distinguishes CLI missing/installed/conflict/active/ready; `harpoon docker env` → `export DOCKER_HOST=...` (preferred context remains).

## Error Messages
Duplicate start → `HARPOON_ALREADY_RUNNING Harpoon is already running (PID ...) Docker: ready Try: harpoon status` exit 10; invalid cpu/memory → `cpus must be 1...8`/`memory must be 512|768|1024` exit 1; malformed config → `Harpoon configuration is invalid` + path + hint; missing log → `no log at ...`; port collision → `already allocated` via Docker; unsupported bind → `500 host path not shared`.

## Exit Codes
`0` success, `1` general (validation, config, docker), `2` unknown command, `5` validation (memory/cpus), `7` VM start failure, `10` already running (stable).

## Logs
