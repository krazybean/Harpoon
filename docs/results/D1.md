## 5 Resource Discovery (Phase 4)

**Conceptual flow:**
`Harpoon.app/Contents/Resources/harpoon/lib/harpoon/{Image-virt,harpoon-initramfs.cpio.gz,harpoon-root.img}` (template, read-only)
  ↓ `RuntimeConfig.resolveRootDisk()` first start
`~/Library/Application Support/Harpoon/data/harpoon-root.img` (persistent writable, `cp -c` APFS clone, fallback `ditto`/`FileManager.copyItem`, verify size)
  ↓ runtime uses writable disk
`Harpoon.app/Contents/Resources/...` never mutated (template).

Reuse `cp -c` where practical; verify upgrades preserve `~/Library/.../harpoon-root.img` (no overwrite if exists). Documented.

**Implementation:** `RuntimeConfig.swift` `installedLibDir()` now checks:
- `Bundle.main.resourceURL` → `harpoon/lib/harpoon`, `bundle-resources/harpoon/lib/harpoon`, `harpoon`, `bundle-resources/harpoon`, `Image-virt` flat
- Executable relative `../Resources/harpoon/lib/harpoon`, `../Resources/bundle-resources/harpoon/lib/harpoon`, `../../Resources/...`
- Then legacy `/usr/local/lib/harpoon`, `/opt/homebrew/*`, then `binDir/../lib/harpoon`
`resolveResource(named:fallback:)` checks `installedLibDir` first, then CWD, then exec relative, then fallback.
`resolveRootDisk()` provisions to `~/Library/.../Harpoon/data/harpoon-root.img` via `cp -c` (clone), verifies logical size, preserves existing user disk on replacement/relaunch.
